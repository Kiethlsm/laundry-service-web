# Phase 10 local package evidence

Initial four named checks were red before the release manifest, local demo launcher, guide and rollback generator existed (`red.txt`). `red-client-scanner.txt` proves the client-boundary fixture had not been scanned; the scanner now accepts the explicit fixture root, rejects an injected fake server marker and accepts a clean positive control. The final production build is separately scanned after build by the phase gate. This checks known synthetic/server/test markers, not every possible secret or hosted configuration.

`P10_ROLLBACK` executes every migration prefix on a unique local PG17.11 fixture, generates and executes its inverse SQL, and compares original table/column/function ACLs, functions, policies, triggers, constraints/indexes, default privileges and canonical row hashes. A populated new table refuses rollback without deleting its row. Original profile activation/revision changes and modified original rows also block the generated script. No CASCADE, DML deletion, truncate or trigger bypass is used. Restored table privilege lists may contain the word TRUNCATE as a privilege; the negative SQL check correctly distinguishes that from executing TRUNCATE.

`rollback-development.txt` records the earlier focused rollback run; the cumulative gate is the final authority. The generated five SQL artifacts are bound to a separate exact synthetic local database and intentionally unusable on hosted. Local logical catalog comparison excludes PostgreSQL dropped-attribute tombstones, object OIDs and sequence state; future hosted export/rehearsal must cover sequence/auth/storage requirements separately. Refusing rollback after writes is a safety boundary, not a full recovery strategy for an active shop.

The HTTP smoke initially expected a 307 response for `/admin`. Current Next streams a 200 shell with its exact `__next-page-redirect` meta tag (`1;url=/admin/login`), documented in the bundled `redirect.md` streaming behavior. The test now asserts that exact denial directive and absence of admin operation controls/private fixture address, or the standard 307 Location. It does not accept a generic 200. P09 independently proves actual browser navigation to login without a session and complete authorized actions.

No external integration, real provider/authentication service, hosted API, deploy, remote CI, quote/ledger migration on hosted, or commercial readiness is claimed. The README replaces the old baseline-only instructions so it cannot encourage an unsafe hosted rerun of schema/functions. Approval for a future hosted rollout remains necessary; its exact rollback and safe immutable-fixture cleanup require the fresh private snapshot and separate review.

`red-ci-history.txt` catches the release evidence check's incompatibility with a shallow Actions checkout. The CI definition now fetches commit history and runs the exact P10 cumulative gate, including post-build client checks. This is locally checked workflow configuration, not an executed GitHub Actions result. No new package/action dependency was added.
