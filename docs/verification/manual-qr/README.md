# Manual Techcombank QR integration

Local branch only. No schema migration, real payment activation, hosted write, push or deployment. The accepted portfolio ledger and booking rules remain simulated. This change applies the user's supplied QR to the existing bank-transfer choice and booking confirmation; cash does not show it. The admin order detail can expand the same receiving details for open transfer orders.

The user-supplied receiving name/account are displayed exactly as provided (without the image's account-type prefix). The PNG was prepared by built-in imagegen with a crop-only/preservation prompt. A local analysis compared the original and prepared 33×33 QR pattern at 1089 module centers: 0 differences. Provenance and SHA-256 are in asset.json. The app serves that PNG with unoptimized next/image, preserving the saved bytes; CSS frames the white QR card while the surrounding HTML displays the recipient and account at readable size. No generated QR payload, amount or memo is embedded into the static image.

The panel labels estimates, instructs the customer to wait for confirmed costs, displays a per-order memo only after a valid returned order code, supports copy with Vietnamese failure recovery and downloads the original PNG. It never reports a payment or claims a customer notification was sent. No cosmetic “I paid” button is added without durable server handling. The existing admin demo receipt action remains simulated, not actual bank reconciliation. Real-money acceptance still requires the separately reviewed financial schema/workflow and approved deployment; adding a QR is not that activation.
